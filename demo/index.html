tooltip-turn

Rest the mouse on a button in the first row until its tooltip shows, then slide along the row. Do the same in the second row and compare. Source on GitHub.

Things to notice

  1. In the first row, the first tooltip waits 400 ms. After that, each one opens as soon as you reach its button, and the last one goes. There is never more than one.
  2. Sweep the mouse quickly across the first row from outside it. Nothing opens, because each new button starts the wait again.
  3. Move off the row for half a second, then come back. The first tooltip waits again.
  4. Click the button you're resting on, tap one on a phone, or Tab to one. It opens straight away. Tap it again, press Escape, or tap somewhere else to close it.
  5. In the second row, every tooltip waits, so sliding along it is slow.

Why

I wanted tooltips to take turns the way they do on a Mac. Only one shows at a time. The first one waits a moment, so a mouse passing over a toolbar doesn't set them all off. Once one is open, you're reading them, so the next opens at once. A click, a tap or a key never waits, because you asked for the tooltip.

The wait lives in tooltip-turn, not in the tooltips. These ones are a few lines of plain JavaScript, and it works the same with a tooltip library, as long as the library's own delay is 0.
